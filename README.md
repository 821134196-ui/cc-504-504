# 食堂新食材盲评选样系统

食堂选用新食材前收取供应商试样并**盲评**：收样登记品类、产地、到货温度、批次、封存编号；
评审人在**不知道供应商名称**的情况下记录口感、规格与烹调损耗；最后由**两人同时揭盲**，
统一形成选用意见并复核。封签破损、到货超温、样品过期、评审人回避、评分漏项、供应商撤样
**全部留痕**。

零第三方依赖，仅使用 Python 3 标准库（`http.server` + `sqlite3`）。

## 一条命令启动

```bash
python3 run.py            # 初始化数据库+种子数据（含封签破损样例），启动 http://127.0.0.1:8000
python3 run.py --reset    # 清空演示库与照片后重新播种
python3 run.py --port 8080
```

## 页面与规则

- **收样登记**：品类/产地/到货温度/批次/封存编号/库位/供应商/本地照片；超温自动判异
- **样品台与封样库位**：评审人只看得到编号与「盲样」，揭盲后才显示供应商
- **盲评表**：按样品编号呈现；**感官评分（口感、规格）与实测损耗分区**；三项不得漏项
- **回避申请/审批**：批准后该评审人不能评分、不能参与揭盲
- **揭盲页**：对照各评审意见；需两名不同人员确认；揭盲前任何身份查询被拒绝并审计
- **结果复核**：选用意见形成后逐人复核
- **访问审计**：身份查询被拒、采购员填分被拒、回避、评分、竞态落败等全部入库

配色为白、炭灰与少量食材绿；评分一律以数字+描边胶囊呈现，**不用颜色暗示高低**。

## 数据与审计

- SQLite：`data/tasting.db`
  - 评分 `scores`、揭盲 `unveils`、回避 `recusals`、选用 `decisions`、复核 `reviews`
  - 全程留痕 `events`、访问审计 `audit_logs`、模拟通知 `notifications`
  - 部分唯一索引：一个封存编号只能关联一份**当前**（未撤样）样品
- 样品照片：`data/photos/`（本地文件，登记时上传或播种时生成占位图）
- 通知：`MockNotifier` 适配器，落库 `notifications` 表，不访问外部服务

## 并发揭盲如何保证只有一次结果

`unveil_confirm` 以 `BEGIN IMMEDIATE` 进入写事务（SQLite 写事务串行化），
`unveils.sample_id` 上还有 `UNIQUE` 约束兜底：两人同时点“确认”，只有一个事务插入成功，
落败方收到「结果已产生」并写审计；同一人重复点击幂等不占位。

## 测试（42 个，均基于标准库 unittest）

```bash
python3 -m unittest discover -s tests -v
```

- `test_anonymity.py`：**匿名隔离**——揭盲前身份查询被拒并审计、评审页不含供应商、采购员/管理员不能填分
- `test_unveil_race.py`：**揭盲竞态**——多线程并发第二确认/两组并发揭盲，`unveils` 恰好一条
- `test_recusal.py`：**回避**——申请审批留痕，批准后拦截评分与揭盲
- `test_score_integrity.py`：**评分完整性**——漏项、取值范围、每人一条、DB CHECK、异常态不可评、封存唯一与撤样释放
- `test_http_flow.py`：HTTP 全流程冒烟（登录、匿名展示、双人揭盲、选用与复核、审计权限）
